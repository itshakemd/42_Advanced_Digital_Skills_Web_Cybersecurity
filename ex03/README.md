# Project 00: Linux, Git, and GitHub

This project practices essential command-line and version-control skills. It covers navigating a Linux filesystem, creating directory structures, manipulating files and text streams, tracking work with Git, and publishing a repository on GitHub.

## What I Practiced

- Navigating with `pwd`, `cd`, and relative paths
- Creating directories and nested paths with `mkdir -p`
- Creating, writing, appending, copying, renaming, and deleting files
- Using the Git working directory, staging area, and repository
- Following the edit-add-commit-push workflow
- Publishing work to a public GitHub repository

## Why Git Makes Development Easier

Git makes development easier because it safeguards my code by saving known versions of the project. Its history shows what changed, who changed it, and why, so I can understand the project's progress or return to an earlier version when something goes wrong. Git also helps a team collaborate: each person can work on changes independently, review them, and combine them without blindly overwriting another person's work.

## Basic Git Workflow

1. Edit the project files.
2. Run `git status` to inspect the changes.
3. Stage the intended changes with `git add`.
4. Save the staged snapshot with `git commit`.
5. Upload the commits with `git push`.
